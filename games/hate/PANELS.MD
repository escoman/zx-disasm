# H.A.T.E. — как получить изображения панелей HUD

Панели HUD (логотип + шкала слева вверху, SCORE/MAX/HIGH справа внизу) — это
**готовый статичный образ экрана**, а не результат рендеринга. Образ лежит в
кольцевом буфере по адресу `$A000–$BFFF` (6912 байт: 6144 bitmap + 768 атрибутов)
и выгружается на экран один раз при входе в сцену.

## Краткая модель

1. Образ `$A000` загружается RLE-разворачивателем `$5B8C` из сжатого блока 6 TAP-файла.
2. Став `$9F1C` (`LD HL,$A000 / LD DE,$4000 / LD BC,$2000 / LDIR`) копирует образ на экран.
3. Блиттер рельефа `$D35E` за проход восстанавливает только **диагональный клин**
   (485 клеток из 768); **299 клеток панелей не затираются вовсе** — они живут в
   экранной памяти постоянно от кадра к кадру.
4. Поверх образа оконный движок `$EE17` кладёт цифры SCORE/HIGH и текст субтитров,
   а масочный конвейер `$DECB`/`$DFAA` рисует узкие полоски индикаторов в кольцо.

## Извлечение образа панелей

```bash
# Сохранить образ $A000 в .scr и сверить с игровым экраном.
python3 tools/panel.py dump tmp/probe_play.txt 100 2000 data/gfx/hud_panels.scr
# -> data/gfx/hud_panels.scr (6912 байт)
# -> data/gfx/hud_panels.png (визуализация)
# -> render/38_panel_image.png (образ $A000 слева, игровой экран справа)
```

Параметры:
- `tmp/probe_play.txt` — скрипт клавиатуры (запуск игры, миссия)
- `100` — кадр, на котором снимаем образ `$A000` (уже после выгрузки на экран)
- `2000` — кадр геймплея для сравнения
- `data/gfx/hud_panels.scr` — выходной файл

Результат сверки: **286 из 299 клеток** панелей совпадают побайтно с образом `$A000`.
Расходятся 13:
- 9 клеток мигающей диагональной рамки (`$57 ↔ $A8/$AB`);
- 4 клетки динамических показаний (сегменты шкалы, цифры SCORE/MAX/HIGH) — их
  поверх образа кладёт оконный движок `$EE17`.

## Доказательство, что панели не затираются

```bash
# Эксперимент с маркером: заливаем экран значением $5A и смотрим, какие клетки
# восстанавливает каждый проход движка.
python3 tools/hud3.py tmp/probe_play.txt 2000 tmp/hud_wipe
# -> render/39_hud_blindspot.png (экран после затирания vs реальный кадр)
```

Результат (кадр 2000):
- окно субтитров `$D9D6` — 54 байта (строка 6, колонки 2..7);
- блиттер рельефа `$D35E` — 3792 байта (485 клеток клина);
- **2304 байта = 299 клеток не восстанавливает ни один проход** — это обе панели.

## Когда панели появляются на экране

```bash
# Отслеживаем изменения в клетках панелей кадр за кадром.
python3 tools/panel.py when tmp/probe_play.txt 0 2100 60
# Единственный всплеск >60 байт: кадры 1235-1237 (переход заставка → меню).
# В геймплее меняются только 9 клеток мигающей рамки.

# Снимки экрана в ключевых кадрах перехода.
python3 tools/panel.py shots tmp/probe_play.txt 1300 1234 1235 1236 1237 1238 1240
# -> tmp/panel_01234.png ... tmp/panel_01240.png
# -> tmp/panel_strip.png (лента)
```

## Кто рисует панель

```bash
# Пошаговая трассировка записей в контрольные клетки панелей.
python3 tools/panel.py who tmp/probe_play.txt 1234 1241
# PC = $9F26 (LDIR $A000 → $4000) — виновник всех записей.
```

Став `$9F1C`:
```
$9F1C DI
$9F1D LD HL,$A000        ; bitmap образа
$9F20 LD DE,$4000        ; экран
$9F23 LD BC,$2000        ; 8192 байта = картинка + атрибуты с хвостом
$9F26 LDIR               ; <<< этот PC фиксирует трассировка
$9F28 XOR A / LD ($C2F8),A / JP $C2B1
```

Перед ним тот же став делает `$7C00 → $6300` (шрифт, `$2400` байт), `CALL $EE17`
со строкой `$9F2F` («HOSTILE-ALL-TERRAIN ENCOUNTER»), `CALL $9F4B` и `CALL $8000`.

## Палитра атрибутов панелей

| Атрибут | Значение | Где используется |
|---------|----------|------------------|
| `$02` | чёрный ink / красный paper | рамка панели |
| `$06` | чёрный ink / белый paper | текст, логотип |
| `$10` | красная бумага | фон панели SCORE |
| `$03` | чёрный ink / маджента | декоративные элементы |
| `$07` | яркий белый | текст |
| `$38` | белая бумага | поле разрядов SCORE/MAX/HIGH |
| `$15` | циан по красному | сегменты шкалы («зелёный» на скриншоте) |

## Динамические элементы поверх образа

Эти клетки меняются в геймплее поверх статичного образа:

| Клетка | Содержание | Кто рисует |
|--------|------------|------------|
| 9 клеток рамки | мигание `$57 ↔ $A8/$AB` | блиттер рельефа (попадаются в клин) |
| `(22,18)` | сегменты шкалы | масочный конвейер `$DECB`/`$DFAA` |
| `(29,20)`, `(29,21)` | цифры SCORE/MAX | оконный движок `$EE17` |
| `(29,23)` | значение HIGH | оконный движок `$EE17` |

## Масочный конвейер индикаторов

Узкие вертикальные полосы приборов рисуются отдельным конвейером `$DDED → $DECB/$DFAA`.
Запись списка `$FE64` (8 байт): `[класс][режим][BC=дескрипторы][ряды][колонка][назначение]`.

```bash
# Пошаговая трассировка обхода списка.
python3 tools/hud.py tmp/probe_play.txt 2000 tmp/hud_walk.json --frames 8 --walk
```

В геймплейном кадре две записи:
- `$FE64`: класс `$08`, режим 2, `BC=$60D4`, 2 ряда, назначение `$9BBC`;
- `$FE6C`: класс `$00`, режим 1, `BC=$6072`, 4 ряда, назначение `$ABBD`.

Композиция идёт **только в кольцо** — экран за весь обход не меняется ни на байт.
