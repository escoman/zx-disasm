# H.A.T.E. — графический конвейер и ассеты

Разбор пункта C (графика). Все выводы проверены дизассемблированием
(`HATE_engine_final.skool`) и диффом снапшотов mid-mission
(`run10_56000.z80` vs `br5_42000.z80`).

## Главный вывод: графика ВЕКТОРНАЯ, спрайт-шитов нет

H.A.T.E. (Vortex, 1989) не использует классические битмап-спрайты.
Всё содержимое кадра строится растеризаторами из потоков-форм:

1. **Шрифт** — единственный «настоящий» битмап-ассет.
   - Адрес: **$6300**, 96 глифов × 8 байт, MSB=левый пиксель, 8×8.
   - Индекс = код символа − $20 (`$EE54: SUB $20; ×8; +$6300`).
   - Бит 7 кода символа в текстовых строках — «пропустить» (разрыв строки,
     $FF = конец окна): рутина окна $EE17.
   - Три варианта баз ($40/$48/$50 в $EE1E/$EE2C/$EE34) — самомодифицируемый
     указатель $EE13: текст может рисоваться из разных страниц (смещение
     регистрового банка). Для порта достаточно одного шрифта.
   - Артефакт: `font_6300.bin` (768 Б) + лист `font_6300.png`.

2. **HUD/иконки** — рутина $DE2C–$DECB: «вытянутые» 8-пиксельные вертикальные
   полосы (5–6 байт, blit `LD A,(DE): AND (HL): LD (HL),A` $DEE6–$DF05).
   Элементы панели приборов — узкие вертикальные индикаторы (топливо/высота),
   паттерны приходят потоком записей (буфер указателя $DD66, записи по 6 байт:
   [x-страница][?][паттерн A][16-бит указатель DE]).
   Банк $6500–$6539 — рантайм-скретч под эти полосы (в снапшоте — мусор,
   не статичный ассет).

3. **Линейный растеризатор форм** — $D105–$D150:
   - Поток байтов-опкодов; $FF = конец объекта.
   - Байт >> 1 → индекс в таблице экранных смещений $C9FE (предвычисленные
     адреса колонок); далее 8 пикселей колонки пишутся слиянием атрибутов
     (`AND $1F` — X, `AND $E0 | (HL)` — Ink/Paper биты).
   - Это отрисовка «вертикальных штрихов» — из них собраны каркасные
     горы/объекты.

4. **Рельеф** — процедурный: рендерер пишет в scratch-строку $6000–$62FF
   (заполнение LDIR из $D0EF), backbuffer $8400–$BFFF, затем части — на
   экран $4000/$6000-адресация. Никаких тайл-таблиц.

## Статичный банк данных $653A–$8008

Дифф двух distant mid-mission снапшотов: 6863 байта инвариантны
→ это **статичный ресурс** (потоки форм объектов/уровней + таблицы),
access — только через вычисляемые 16-битные указатели из записей
(прямых `LD HL,$65xx+` в коде нет, кроме $D51D→$8000 = backbuffer).
Артефакт: `bank_653A.bin` — сырой дамп для портирования потоков.

## Упаковка в TAP (для полноты картины)

- Блок 6 (35496 Б @ $5F74) — INXS-крауншер («Skewed by INXS SOFTWARE '89»,
  сигнатура $5CC9) + поверх — собственный RLE движка ($5B8C):
  байт $97 = escape; далее count-байт: bit7=1 → N нулей (N<3 → N литеральных
  $97); bit7=0 → N повторов следующего байта; N=0 → 256. Развёртка
  обратная: HL $E9F6↓, DE $FFFF↓, стоп HL==$5FB3.
- Python-симуляция RLE разворачивает 35428→41091 Б, но финальный контент
  совпадает с снапшотами лишь после INXS-слоя — для офлайн-репаковки нужон
  разкрутчик INXS (63-байтный став @ $5F74). В работе не потребовалось:
  ассеты берутся из снапшотов напрямую.

## Что это значит для порта на Вектор-06Ц

- Переносим: шрифт (768 Б, ложится в ROM Вектора 8×8 как есть),
  потоки форм (bank_653A.bin) + семантику опкодов $D105, алгоритм
  процедурного рельефа, композицию HUD (узкие полосы + атрибуты →
  у Вектора свои 2 банка по 1024 символа 8×8).
- Не переносим: битмапы экрана — их нет; растр собирается на лету.
