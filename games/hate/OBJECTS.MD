# H.A.T.E. — как получить объекты на рельефе

Всё, что видно на экране H.A.T.E. — ландшафт, дорога, камни, плиты, юниты —
рисуется через **кольцевой буфер** `$8000–$BFFF` (16 КБ) и один общий блиттер `$D35E`.
Отдельных спрайтов для объектов рельефа нет: они собраны из клеток 8×8 того же банка
шаблонов `$C400`, что и дорога.

## Краткая модель конвейера

```
банк шаблонов $C400 (64 клетки 8×8)
      ↓
страница кольца = столбец ландшафта из 16 клеток ($D4E9/$D51D)
      ↓
блиттер $D35E: POP HL из списка $D5B2 → 8 байт вверх по экрану
      ↓
экран $4000 + атрибуты $5800
```

Кольцо — **скользящее окно**: видимый столбец экрана `x` начинается со смещения
`off(x)` внутри кольца, и `off(x+1) = off(x) + $1FC` (шаг +508). Это даёт
перспективу без единого умножения в кадре.

## Дамп кадра для работы

```bash
# Полная остановка на нужном кадре и сохранение всей памяти $4000-$FFFF.
python3 tools/hate_run.py data/scripts/br5_demo.txt 1600 /tmp/frame1600 --dump-at 1600
# -> /tmp/frame1600/all.bin       (вся память $4000-$FFFF, 49152 Б)
# -> /tmp/frame1600/screen.png    (видимый экран)
# -> /tmp/frame1600/frame.txt     (PC, SP, T-state на момент дампа)
```

Все последующие инструменты работают с этим дампом.

## Банк шаблонов $C400

64 записи по 8 байт. Каждая запись — 8 строк клетки 8×8 (байт = 8 пикселей
горизонтально, MSB = левый пиксель). Код `$00` — пустая клетка (все нули): блиттер
её всё равно пишет, поэтому она стирает старое содержимое.

```bash
# Визуализация банка шаблонов.
python3 tools/render_objects.py /tmp/frame1600 render/
# -> render/01_pattern_bank_C400.png  (все 64 шаблона с кодами)
```

## Страница кольца

Страница = один столбец ландшафта из 16 клеток:

```
+$00..+$7F : 16 клеток × 8 байт = 128 байт
             (клетка 0 = нижняя строка столбца, клетка 15 = верхняя)
+$80..+$FF : та же колонка, сдвинутая на 2 пикселя вправо (для подпиксельного скролла)
```

Сборка страницы — `$D4E9`/`$D51D`: первые 8 байт — «специальная клетка» из `$C4B8`
или `$C4C0` (4 варианта ближней клетки дороги, сменяемых по фазе), затем 15 клеток
из записи столбца `$C6xx` (коды шаблонов).

```bash
# Визуализация страницы кольца.
python3 tools/render_objects.py /tmp/frame1600 render/
# -> render/02_ring_page.png  (страница + сдвинутая копия)
```

## Блиттер и список адресов экрана

Блиттер `$D35E` — самая «горячая» процедура кадра. Он читает список `$D5B2`
(528 слов = 264 клетки), где каждое слово — адрес на экране, и копирует 8 байт
из кольца в экранную память столбец за столбцом:

```
LD SP,$D5B2           ; список адресов экрана = стек
...
POP HL                ; адрес очередной клетки
8×(LD A,(DE); LD (HL),A; INC E; DEC H)  ; 8 байт вверх по экрану
```

`DEC H` уменьшает адрес на 256 — это переход на одну пиксельную строку вверх внутри
того же знако-столбца. Поэтому 8 байт подряд из кольца ложатся вертикальной полосой
8×1 на экране.

```bash
# Силиуэт клеток из списка $D5B2 поверх реального кадра.
python3 tools/render_objects.py /tmp/frame1600 render/
# -> render/03_terrain_silhouette.png  (красная сетка = клетки блиттера)
```

## Что видно на экране: объекты рельефа

Объекты, которые выглядят как «камни» и «плиты» на ландшафте, — это **не отдельные
спрайты**, а клетки из того же банка `$C400`, уложенные в кольцо. Если разрезать
видимый объект на клетки 8×8 и искать каждую в банке (с точностью до вертикального
сдвига 0…7 строк), находится ближайший код.

```bash
# Разложение объектов на клетки банка.
python3 tools/decompose.py /tmp/frame1600 render/
# -> render/05_object_cells.png  (crop / rebuilt-from-codes / code grid)

# Монтаж всех видимых объектов с сеткой 8×8.
python3 tools/render_objects.py /tmp/frame1600 render/
# -> render/10_objects_montage.png
# -> render/20_crystal_small.png .. render/24_block_edge.png
```

Известные объекты с кадра 1600:

| Файл | Что | Размер в клетках |
|------|-----|-------------------|
| `20_crystal_small.png` | мелкий кристалл (ближний к дороге) | 4×3 |
| `21_crystal_left.png` | кристалл левее | 3×3 |
| `22_plate.png` | плоская плита/платформа | 3×3 |

## Восстановление экрана из кольца

Экран — непрерывный кусок кольца, свёрнутый с шагом `+$1FC`:

```
S(x)[n] = ring[(off(x) + n) mod $4000]
off(x+1) = off(x) + $1FC   (mod $4000)
```

```bash
# Реконструкция: кадр / восстановление только из кольца / карта расхождений.
python3 tools/render_playfield.py /tmp/frame1600 render/
# -> render/04_reconstruction.png
```

Совпадение — в среднем 122 из 192 байт на столбец. Расхождения объясняются:
- HUD-панелями (блиттер их не затирает, § см. `PANELS.MD`);
- юнитами, которые уже стёрты из кольца, но ещё видны на экране;
- пересечением границы двух столбцов ландшафта.

## Таблица высот/трассы

`$6000–$62FF` — 24 × 32 байта (высота/проходимость по столбцу). Читает `LE3BF` —
скан клиренса для ИИ и проверки «можно ли ехать».

```bash
# Дамп таблицы трассы.
python3 tools/hate_run.py data/scripts/br5_demo.txt 1600 /tmp/frame1600 --dump-at 1600
# -> /tmp/frame1600/band.bin  ($6000-$62FF, 768 Б)
```

## Подпиксельный скролл

`($C32E)` = номер страницы (столбец ландшафта), `($C32F)` = половина страницы
(`$00`/`$80`, то есть 0 или 2 пикселя горизонтально). Вторая половина каждой
страницы кольца (`+$80..+$FF`) содержит ту же колонку, сдвинутую на 2 пикселя
побитовым сдвигом (`$D440`/`$D589`). Это позволяет прокручивать ландшафт с шагом
2 пикселя, не пересобирая страницу.

Нечётная фаза (1 пиксель) делается вариантом `$D45B` (`RRA/RR C` — сдвиг на 1).

## Записи объектов на ландшафте

Статические объекты рельефа (криаллы, плиты) — это не записи `$C000`, а часть
ландшафта: их коды шаблонов лежат в записях столбцов `$C6xx` и упаковываются в
кольцо при сборке страницы.

Динамические объекты (юниты) — это записи `$C000–$C0FF` (16 слотов). Их проекция,
форма и вывод в кольцо описаны в `SPRITES.MD`.

## Порядок кадра

Полный порядок прохода (см. `ENGINE.MD` §7):

1. `$D050` — логика/ввод/статус
2. `$EFA5` — проекция объектов; `$D9D6` строит списки; `$DD44` снимает фон в `$F800`
3. `$EAE3` — композит юнитов в кольцо (`(ring & mask) | value`)
4. `$D2E3`/`$D35E` — **блит ландшафта+юнитов** кольцо → экран
5. `$D338` — атрибуты по тому же списку
6. `$DD6C` — восстановление фона из `$F800` (кольцо снова чистый ландшафт)
7. `$EDCA`/`$EE17` — окна и текст HUD
8. `LE3BF` — скан трассы (ИИ/клиренс)
