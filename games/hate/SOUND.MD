# SOUND.MD — звук H.A.T.E.: формат, адреса данных, извлечение

Игра: Vortex Software, 1989, ZX Spectrum 48K. **AY-чипа нет** — весь звук
делает 1-битный бипер через `OUT ($FE),A`. Звуковых движка два, и они
независимы:

| Движок | Где играет | База кода | Листинг |
|---|---|---|---|
| Музплеер заставки | титул/attract | `$8000–$85C5` | `asm/HATE_title.asm` |
| SFX + бипы меню | миссия, меню | `$F1AA–$F2DF` | `asm/HATE_engine.asm` |

## 0. Готовые артефакты (`sound/`)

| Файл | Что это |
|---|---|
| `sound/title_music.wav` | музыка заставки, 38.54 с, 44100 Гц/16 бит/моно |
| `sound/title_music.txt` | лог всех переключений динамика: `t_state кадр PC значение` |
| `sound/sfx_0_swept.wav` | бит 0 `$F2BF` — свип, 0.04 с |
| `sound/sfx_1_swept.wav` | бит 1 — свип, 0.02 с |
| `sound/sfx_2_swept.wav` | бит 2 — свип, 0.02 с |
| `sound/sfx_3_tone.wav` | бит 3 — тон, 0.02 с |
| `sound/sfx_4_swept.wav` | бит 4 — свип, 0.02 с |
| `sound/sfx_preview.wav` | все пять эффектов подряд, по 3 повтора (как в игре), 5.3 с |

Воспроизводятся из оригинального кода (не синтез «по мотивам»): эмулятор
SkoolKit гоняет настоящие процедуры, WAV собирается из интервалов между
реальными `OUT ($FE)` (`skoolkit.audio.AudioWriter`, 48K-тайминги).

Одиночный `sfx_k_*.wav` — это **одно** срабатывание (1–2 кадра, 0.02–0.04 с),
на слух он воспринимается как щелчок. Для проверки слушай `sfx_preview.wav`:
каждый эффект повторён 3 раза подряд (как при удержании условия в игре),
между эффектами пауза 0.5 с.

## 1. Физический формат (общий для обоих движков)

```asm
        LD A,$18        ; бит 4 = динамик (бит 3 = MIC), маска $18
        OUT ($FE),A
```

- Звук = последовательность переключений бита 4. Полупериод тона равен
  интервалу в T-состояниях между переключениями; 3 500 000 T/с.
- **Важно при захвате:** генераторы пишут в порт на *каждой* итерации
  `DJNZ` с неизменным A (внутри полупериода). Ступенькой звука является
  только смена бита 4 — при записи WAV нужно стробировать по `value & 0x10`
  (так делает `skoolkit.trace.Tracer._write_port`, так же сделано в
  `tools/sound_extract.py`). Иначе частота завышается в сотни раз.
- Амплитуда бинарная (0/100%); в WAV писатель SkoolKit применяет
  moving-average фильтр, чтобы не было щелчков и алиасинга.

## 2. Музыка заставки — плеер `$8000–$85C5` (`HATE_title.asm`)

### 2.1 Карта кода

| Адрес | Метка | Роль |
|---|---|---|
| `$8000` | `L8000` | точка входа: обмен рабочего окна с копией, затем шаг плеера |
| `$803A–$85C5` | — | рабочее окно плеера: код + данные, ровно `$058C` байт |
| `$8109` | `L8109` | главный цикл: `EI`/`HALT` (строго 1 шаг на кадр), выбор под-демо из `$843D` |
| `$813C` | `L813C` | разбор байткода партитуры: op `0A` берёт пару байт как указатель |
| `$8243` | `L8243` | диспетчер звуковых событий (читает поток) |
| `$82A3` | `L82A3` | голос A: подстройка периода (инкремент счётчика) |
| `$82C1` | `L82C1` | голос A: выдаёт импульсы, `OUT` в `$82D1` (`$18`) и `$82D9` (`$00`) |
| `$8305` | `L8305` | голос B: подстройка периода |
| `$8323` | `L8323` | голос B: импульсы, `OUT` в `$8333`/`$833B` |
| `$836A`/`$8375` | `L8323_5` | пауза: `OUT $18`, задержка `DE=$012C`, `OUT $00` |
| `$8389` | `L8323_8` | шум: 150 пар байт из ROM начиная с `$0064`, маска `$18` (взрывы/удары) |
| `$83A6`, `$83B9`, `$83D1` | `$839A`, `$83C6`, `L8398_0` | семейства тонов для событий 4/5/6 (свой `OUT` в каждом) |

Количества переключений за 38.5 с (из `title_music.txt`):
`$8333`×5703, `$833B`×5741 (голос B), `$82D1`×3109, `$82D9`×3123 (голос A),
`$8389`×3388 (шум), `$83A6`×500, `$83D1`×200, `$83B9`×152, `$836A`/`$8375`×111.

### 2.2 Двойная буферизация рабочего окна

`L8000` копирует `$058C` байт между `$803A–$85C5` и второй копией, адрес
которой берётся со стека (передаётся вызывающим), затем работает с `$803A`.
Поэтому **все адреса ниже валидны для «активного» окна `$803A…`** и
повторяются в копии.

### 2.3 Поток событий (`$8243`)

Самомодифицирующийся указатель `$8250/$8251` сканирует поток:

- `$85A3` — поток A (голос A): `02 00 00 02 03 00 02 00 00 00 02 00 03 02 …`
- `$85B1` — поток B (голос B): `00 01 05 04 04 04 04 04 00 05 05 05 05 05 00 06 06 06 06 01 00 …`

Коды (проверено по диспетчеру `$8243`):

| Код | Действие |
|---|---|
| `0` | «пусто»: ничего не менять, продолжать озвучивание |
| `1` | конец потока B → указатель `$8250` сбрасывается на `$85A3` (закольцовка) |
| `2` | пауза (`$836A`/`$8375`) |
| `3` | шум (`$8389`) |
| `4`,`5`,`6` | тональные семейства `$839A` / `$83C6` / `L8398_0` |

### 2.4 Партитура и самомодификация

- Байткод анимации/партитуры: `$8473` (опкоды `0A`/`09`/`0B`/`0C`; `0A`
  содержит 2-байтный указатель на пару параметров).
- Таблицы переходов: `$843D` (указатели потоков под-демо), `$83FC` (заглушки
  обработчиков).
- Самомодифицируемые ячейки: голос A — `$82CA` (начальный период),
  `$82CC` (инкремент периода), `$82D0` (значение для `OUT`), `$82D4`
  (таймер/перезагрузка `$BA`); голос B — `$832C`, `$832E`, `$8332`, `$8336`
  (перезагрузка `$B9`). Прочие: `$8244` (счётчик событий), `$824B`, `$8258/$8259`,
  `$810B/$810C`, `$810E`, `$8116/$8117`, `$817B`.
- Плеер работает от прерывания: `EI` + `HALT` в `$8109` → ровно один шаг
  партитуры за кадр, поэтому темп музыки жёстко привязан к 50 Гц.

**Вывод для порта:** нота здесь — не число, а пара «период + шаг», из которой
`L82A3`/`L8305` инкрементом подстраивают счётчик, а `L82C1`/`L8323` выдают
импульсы. Надёжнее всего воспроизводить логику, а не выводить формулу;
быстрая проверка — по WAV/логу переходов.

## 3. SFX миссии — `$F1AA–$F2DF` (`HATE_engine.asm`)

### 3.1 Карта кода

| Адрес | Метка | Роль |
|---|---|---|
| `$F1AA` | `LF1AA` | обслуживание за кадр (меню, бипы, демо-паузы) |
| `$F284`/`$F288` | `LF1AA_15`/`16` | **тон**: пара `L`(pitch), `H`(len); `OUT` в `$F28E` |
| `$F2A3` | `LF1AA_20` | **свип**: 4 параметра; `OUT` в `$F2B1` |
| `$F2C0` | `LF1AA_24` | резолвер: бит `k` в `$F2BF` → запись `$F2E2 + 5·k` |
| `$F2D9` | `LF1AA_27` | гейт: `flag = 0` → тон (`$F284`), иначе → свип (`$F2A3`) |
| `$F2E2` | — | таблица: 5 записей по 5 байт |
| `$F2BF` | — | битовая карта запросов звука (биты 0–4) |

Вызов в игре — раз в кадр, `LD050_1`:

```asm
        CALL $F2C0        ; LF1AA_24: найти бит, проиграть запись
        XOR A
        LD ($F2BF),A      ; заявка одноразовая (биты сбрасываются)
```

### 3.2 Формат записи (5 байт)

```
+0  flag   0 = тон, ≠0 = свип
+1  B
+2  C
+3  D
+4  E
```

**Тон (`flag = 0`, `LF1AA_15/16`):** пара в `+1/+2` читается как `HL`
(`L = [+1]`, `H = [+2]`):

- `L` — период: полупериод ≈ `(256 − L)` итераций, итерация ≈ 56 T
  (полный период ≈ `(513 − 2·L)·56` T), больше `L` → выше частота;
- `H` — длительность: `H` циклов по 256 итераций (≈ `H·256·56` T);
- `D` и `E` не используются.

**Свип (`flag ≠ 0`, `LF1AA_20`):**

- `HL = (B<<8)|C`; `H` — шаг свипа, `L` — число полупериодов на шаг (`C=L`);
- `D` — счётчик внутреннего `DJNZ`: полупериод ≈ `D·24` T (тон);
- `E` — число шагов; на каждом шаге `D := D − H` → частота плавно плывёт.

Проверка на живом коде: запись `[01,02,04,50,1E]` даёт `L=4`, `E=30`,
всего `L·E = 120` переключений и ≈ `4·24·ΣD ≈ 147 000` T = 0.042 с — совпадает
с `sound/sfx_0_swept.wav` (119 переходов, 0.04 с).

### 3.3 Таблица `$F2E2` (5 × 5 байт)

| Бит `$F2BF` | Адрес | Байты | Тип | Параметры | WAV |
|---|---|---|---|---|---|
| 0 | `$F2E2` | `01 02 04 50 1E` | свип | `HL=$0204`, шаг `H=2`, `D=$50`, `E=30` | `sfx_0_swept.wav` |
| 1 | `$F2E7` | `01 0A 03 14 06` | свип | `HL=$0A03`, шаг `H=10`, `D=$14`, `E=6` | `sfx_1_swept.wav` |
| 2 | `$F2EC` | `01 32 05 1E 03` | свип | `HL=$3205`, шаг `H=50`, `D=$1E`, `E=3` | `sfx_2_swept.wav` |
| 3 | `$F2F1` | `00 14 04 00 00` | тон | `HL=$0414` → `L=$14`, `H=4` | `sfx_3_tone.wav` |
| 4 | `$F2F6` | `01 02 04 42 0A` | свип | `HL=$0204`, шаг `H=2`, `D=$42`, `E=10` | `sfx_4_swept.wav` |

Сразу перед таблицей лежит указатель `$F2E0 = A3 F2` (`$F2A3`) — точка входа
свип-генератора; при выборке записи он не используется.

### 3.4 Кто поднимает биты `$F2BF`

| Бит | Адрес установки | Контекст в коде |
|---|---|---|
| 0 | `$ECF3` (`LECF3`) | добавление объекта в пул: копия 7 байт, `$ECE4+1`, сдвиг `$ECF1`, `$ECE5` |
| 1 | `$E3BF_18` и `$E9CE_30` | объект переведён в состояние удара/гибели (`$E68B=$FF`, `(IX+8)=$20`) |
| 2 | `$E3BF_14` | объект входит в состояние 5 с таймером (разрушение) |
| 3 | `$E5C9_4` | game over / конец миссии (вывод сообщения `$F136`/`$64F6`) |
| 4 | `$E889` | запись координат в `$C003…` (трансляция/сопровождение цели) |

Бит поднимается только на один кадр: `LD050_1` после `CALL $F2C0` гасит весь
байт. Если условие держится (горит объект, идёт обстрел), бит поднимается
каждый кадр → звук превращается в «трещотку»: слышно как серию коротких
бипов, а не как длинный звук.

Отсюда длительность: 1–2 кадра на запрос — 0.02 с у `sfx_1` (`E=6`),
`sfx_2` (`E=3`), `sfx_4` (`E=10`) и у тона `sfx_3` (`H=4`), 0.04 с у `sfx_0`
(`E=30`). Поэтому отдельные `sfx_k_*.wav` как звук почти неразличимы — это
одиночный выстрел; оценивать на слух удобнее по `sound/sfx_preview.wav` (§0).

### 3.5 Прочие бипы (меню, заставка, пауза)

Тот же `LF1AA_16`, но пара `pitch/len` берётся не из таблицы, а из RAM:
`$0F3C` (подтверждение/ABORT, `LD050_4`/`LD050_5`), `$C814` (`LD050_2/3`),
`$8C05` (`LCF32_12`, старт с уровня), `$465A` (`LF1AA_1`),
`$1E9C` (`LF1AA_10`). Содержимое этих ячеек формируется кодом на ходу —
статической таблицей они не являются.

## 4. Сводная карта данных

```
$8000–$85C5   плеер заставки (рабочее окно, двойное буферизованное)
              код: $8000, $8109, $813C, $8243, $82A3, $82C1, $8305, $8323
  $836A/$8375 пауза, $8389 шум (ROM $0064), $839A/$83C6/$8398 тональные семьи
  $843D, $83FC  таблицы переходов
  $8473       байткод партитуры
  $85A3       поток A, $85B1 поток B
F1AA–F2DF     игровые SFX
  $F1AA       LF1AA   (кадровое обслуживание, меню)
  $F284/$F288 тон, $F2A3 свип, $F2C0 резолвер, $F2D9 гейт
  $F2BF       битовая карта запросов
  $F2E2       таблица записей 5×5
```

## 5. Как это получено и как повторить

```bash
cd games/hate
python3 tools/sound_extract.py title 2000   # -> sound/title_music.wav + .txt
python3 tools/sound_extract.py sfx          # -> sound/sfx_0..4_*.wav
python3 tools/sound_decode.py               # таблицы/адреса из skool-листингов
```

`title` идёт от `tmp/HATE.z80` (титул): любой клавишей выходим из «press any
key», дальше attract крутится сам; музыка стартует на кадре ≈ 70 (после
отработки распаковщика загрузчика).

`sfx` сначала прогоняет меню (`SPACE` → `1` → `6` → `SPACE`) — только чтобы
в памяти оказалась резидентная банк-область `$F2E2` (в титульном снапшоте она
нулевая!), затем выполняет заглушку, повторяющую игровой вызов:

```asm
        LD A,1<<k
        LD ($F2BF),A
        CALL $F2C0        ; ровно то, что делает LD050_1
        XOR A
        OUT ($FE),A
```

Так в WAV попадает только сам эффект, без выстрелов и сирен противника.
Дополнительно каждая запись проигрывается 3 раза подряд и все пять
склеиваются в `sound/sfx_preview.wav` (пауза 0.5 с между эффектами).

### Грабли (проверено на практике)

1. **Хук порта.** `ScriptedTracer` в `coverage.py` создаётся с `port_fe=True`,
   и в `__init__` базового `Tracer` `self.write_port = self._write_port`
   *подменяет* метод подкласса. Свой обработчик ставить после `super().__init__`.
2. **Дедупликация.** Без строба по биту 4 число «переходов» завышается в сотни
   раз, частота в WAV — тоже.
3. **4-й аргумент `Simulator.trace()`** — абсолютный порог T-состояний, а не
   длительность. При запуске с середины: `registers[T] + длина`.
4. **`SP`** — единый 16-битный регистр в `registers[12]` (`registers[13]` —
   альтернативный `SP'`). Разбиение на два байта ломает `CALL`/`RET`.
5. **Захват из миссии «как есть»** даёт мусор: противники сами поднимают биты
   `$F2BF`. Для одиночных эффектов вызывать генератор напрямую (см. выше).
6. Бинарник `skoolkit/csimulator*.so` пересобирается без `setuptools`:
   `gcc -shared -fPIC -O2 $(python3-config --includes) c/csimulator.c -o skoolkit/csimulator.cpython-312-x86_64-linux-gnu.so`

## 6. Заготовка для порта на Вектор-06Ц

Оба движка — чистый «pulse-proportional synthesis», DSP не нужен.

```
тон(HL):        ; L = период, H = длительность
  C = H; D = L; E = L-1; A = 0
  repeat C:
    repeat 256:
      OUT(PORT_A), A
      D++; if D == 0: D = L; A ^= 0x10
      E++; if E == 0: E = L-1; A ^= 0x10
  OUT(PORT_A), A

свип(B,C,D,E):  ; H = B (шаг), L = C (тиков на шаг)
  H = B; L = C
  repeat E:
    repeat L:
      A ^= 0x10; B = D
      repeat B: OUT(PORT_A), A        ; B = 8-бит счётчик
    D -= H
```

Для Вектора: `OUT ($FE)` → порт бипера (`FF`), счётчики те же, вместо
`DJNZ` — `DCR B / JNZ`, задержки те же в тактах, но частота кварца другая
(3.0 МГц у КР580ВМ80А в «Векторе-06Ц» против 3.5 МГц у Z80) — при переносе
1:1 звук станет ниже на ~15%, нужно масштабировать счётчики или тактирование.
